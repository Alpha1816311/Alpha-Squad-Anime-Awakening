ALPHA SQUAD: ANIME AWAKENING — REPLIT BUILD PROMPT

You are a senior full-stack engineer, AAA anime game UI designer, cinematic motion designer, and application security engineer.

Build a complete, mobile-first anime-inspired hackathon recruitment platform named ALPHA SQUAD: ANIME AWAKENING.

The result must be an actual runnable application, not a mockup or a written explanation.

DESIGN VISION

Create a premium, attractive, dark anime action-game aesthetic with:

Black and midnight-blue backgrounds.
Electric-blue, violet, cyan, and restrained crimson lighting.
Beautiful original adult anime heroes and heroines.
Confident expressions, striking hairstyles, fashionable outfits, dramatic silhouettes, and powerful character poses.
Cinematic energy portals, glowing eyes, particles, lightning, atmospheric lighting, and elegant motion.
Premium typography and sophisticated spacing.
Responsive interactions designed for Android phones and laptops.

Make the presentation stylish, mature, visually seductive, and appropriate for a student recruitment platform. Do not use explicit sexual content or sexualized minors.

Use original artwork or appropriately licensed assets. Do not depend on copyrighted anime footage or soundtracks.

1. CINEMATIC INTRO

Create a full-screen opening sequence:

Black screen with floating particles.
A dimensional crack opens with blue and purple energy.
Reveal the eyes and silhouette of an original anime hero.
An energy ring expands around an original ALPHA emblem.
Reveal the text:
“THE WORLD BELONGS TO THOSE WHO BUILD.”
Display:
ALPHA SQUAD
ANIME AWAKENING
ONE TEAM. IMPOSSIBLE IDEAS. REAL-WORLD IMPACT.

Show two buttons:

AWAKEN MY POWER
ENTER THE SQUAD

Include Skip Intro, smooth transitions, subtle parallax, glowing buttons, reduced-motion support, and an optional sound toggle. Never autoplay audio.

Implement effects using real CSS animations, SVG, Canvas, or suitable libraries. Do not simply describe them.

2. CHARACTER SELECTION

Create original anime-inspired characters and classes:

Shadow Hunter — Backend Engineering.
Lightning Sorcerer — AI and Machine Learning.
Flame Commander — Leadership and Pitching.
Ice Strategist — Research and Problem-Solving.
Cyber Guardian — Cybersecurity.
Creative Hashira — UI/UX and Design.
Hardware Titan — Arduino, IoT, and Robotics.

Each character needs a distinctive portrait or illustration, aura, color theme, description, and selection animation.

Let applicants optionally select a favorite anime, character, and fictional class. Character preferences must not influence actual recruitment decisions.

3. RECRUITMENT APPLICATION

Create a polished multi-step form with a progress indicator.

Collect:

Full name.
Email.
City and state.
College or institution.
Course or educational background.
Academic year or professional status.
Preferred role.
Secondary skills.
Current skill level.
Previous project experience, if any.
Learning goals.
Availability per week.
Motivation for joining.
Teamwork and problem-solving responses.

Make phone number, portfolio, GitHub, LinkedIn, and resume optional.

Welcome beginners. Do not require certificates or previous hackathon experience.

Use short, engaging questions covering practical problem-solving, deadlines, teamwork, unfamiliar technology, and motivation.

Validate fields and allow applicants to review answers before submission.

4. APPLICATION STORAGE

Persist applications in a database so they survive refreshes and can be reviewed later.

Use the most appropriate supported stack. Prefer TypeScript, a well-structured web application, and Supabase if its credentials are available and configured.

If database credentials are unavailable, implement a clearly labeled development-only fallback and explain its limitations. Do not pretend temporary browser storage is a secure production database.

Generate an application reference only after successful storage.

5. FOUNDER DASHBOARD

Build a separate, authenticated founder dashboard with:

Total applications.
New candidates.
Applications under review.
Interview candidates.
Practical assessments.
Shortlisted candidates.
Selected candidates.

Allow the founder to view candidate responses, filter by role and skills, add private notes, and update statuses.

Statuses:
NEW, UNDER REVIEW, INTERVIEW, PRACTICAL TASK, SHORTLISTED, SELECTED, WAITLISTED, DECLINED, WITHDRAWN.

Enforce authorization on the server. Do not expose candidate information publicly.

6. EMAIL NOTIFICATIONS

Add an integration point for sending a notification to the founder after a successfully stored application.

The founder's email must be configurable.

Use a real email provider if credentials are configured. Keep secrets server-side. If no provider is configured, show clear setup instructions and do not claim an email was sent.

Send a candidate confirmation email if supported.

7. OPTIONAL AI ANALYSIS

Create a candidate-summary feature that can use a configured AI provider to summarize:

Demonstrated skills.
Project experience.
Learning goals.
Availability.
Problem-solving strengths.
Suggested interview questions.
Suggested practical task.

Keep final selection decisions with the founder. Do not fabricate analysis when the AI provider is unavailable.

8. IMPLEMENTATION REQUIREMENTS

First inspect the existing project and available tools.

If the project is empty, initialize it. If code already exists, preserve useful work.

Implement the application in this order:

Working app foundation.
Cinematic landing page.
Character selection.
Recruitment form.
Form validation and submission.
Persistent storage.
Founder authentication and dashboard.
Email integration.

Motion polish and mobile optimization.

Create and edit actual files. Install only necessary dependencies. Run the development server and production build when supported. Fix errors rather than merely describing them.

All visible buttons must perform their intended actions. Include loading, success, error, and empty states.

Do not expose credentials or invent integrations.

At completion, report the implemented features, files changed, test results, missing credentials, and exact steps to run the app.

Do not claim that the application is complete until its main workflow has been tested.
